## 1. 目的と完成条件

### 目的
- Web制作のポートフォリオに載せる「架空の地元密着型 整骨院」のホームページを作る。
- 見せたい相手：個人のお店や会社のオーナー（仕事の依頼主）。
- アピールしたいこと：
  - 実在しそうな、信頼感のあるお店サイトを一通り作れること
  - ターゲットに合わせた設計（集客・予約までの導線）ができること
  - 心地よいアニメーションと、スマホでも見やすいレスポンシブ対応

### 完成条件（すべて満たしたら完成）
- [ ] 6ページ（後述）がすべて表示され、ページ間をナビゲーションで移動できる
- [ ] PC（1280px幅）・タブレット（768px幅）・スマホ（375px幅）で崩れない
- [ ] スマホではハンバーガーメニューが開閉できる
- [ ] GSAP によるアニメーションが動作し、「視差効果を減らす」設定の環境ではアニメーションが抑制される
- [ ] 予約フォームの入力チェックが動き、送信するとデモ完了表示が出る（実際にはどこにも送信しない）
- [ ] 全ページに「ポートフォリオ用の架空サイト」である旨が表示されている
- [ ] 仮画像の差し替えリスト（本書 8章）どおりのファイル名で画像を参照している
- [ ] 外部への送信・保存が一切ない
- [ ] 静的ホスティング（GitHub Pages / Netlify）にそのまま置ける構成である

## 6. アニメーション（GSAP）

- GSAP と ScrollTrigger を CDN（jsDelivr または cdnjs）から読み込む
- 実装する動き：
  1. **ページ読み込み時**：ヒーローのキャッチコピーが1行ずつふわっと表示 → ボタンが表示
  2. **スクロール時**：各セクションの見出し・カードが下からフェードイン（カードは少しずつ時間差で）
  3. **ヒーロー画像**：スクロールに合わせてゆっくり動くパララックス（控えめに）
  4. **装飾の葉っぱ**：ゆらゆらと揺れる小さなループアニメーション（院名「そよぎ」にちなむ）
  5. **ヘッダー**：スクロールすると背景が白くなり、影がつく
- ルール：
  - 動きは「やさしく・ゆっくり・控えめ」。派手すぎる動きは避ける
  - `prefers-reduced-motion: reduce` の場合はアニメーションを無効化し、最初から表示状態にする
  - JavaScript が動かない場合でも、全コンテンツが表示されること（最初から非表示にしない作り）

| ご希望のメニュー | セレクト（各メニュー＋「相談して決めたい」） | ○ |
| 第1希望日 | 日付（今日以降、木曜は選択不可） | ○ |
| 希望時間帯 | セレクト（午前／午後／18時以降） | ○ |
| 第2希望日 | 日付 | － |
| 来院は初めてですか | ラジオ（初めて／2回目以降） | ○ |
| お悩み・ご相談内容 | テキストエリア（500文字まで） | － |
| 個人情報の取り扱いに同意する | チェックボックス | ○ |

### 動作
- 入力中・送信時に入力チェックを行い、エラーは各項目の下に赤字で表示
- エラーがあれば送信せず、最初のエラー項目へスクロール・フォーカス
- 問題がなければ「送信しました（デモ）」の完了画面（モーダルまたはページ内表示）を出す
- **実際の送信・保存は一切しない**（外部サービス、localStorage も使わない）
- 完了表示に「※このフォームはデモのため、実際には送信されません」と明記

## 8. 画像リスト

### 方針
- 実装時は**仮画像**で作る。仮画像は下記ファイル名で `images/` に置き、縦横比を合わせたSVG（グレー背景＋用途名の文字）で作成する。
- 後から本番画像（`.webp` または `.jpg`）に差し替える。差し替え時はHTMLの拡張子を置換するだけで済むようにする。
- **人物が写るもの → 写真素材サイト**（ぱくたそ、写真AC、Unsplash など。利用規約を確認すること）
- **人物が写らないもの → AI生成**
- 全体を「明るく、やわらかく、白〜グリーン寄りの色味」にそろえる。

## 9. 技術・ファイル構成

### 使用技術
- HTML / CSS / JavaScript（フレームワークなし、ビルドなし）
- GSAP + ScrollTrigger（CDN、無料）
- Google Fonts

### フォルダ構成
```
soyogi-seikotsuin/
├── index.html
├── first.html
├── menu.html
├── about.html
├── access.html
├── contact.html
├── css/
│   └── style.css
├── js/
│   ├── main.js        … ハンバーガーメニュー、ヘッダー、共通処理
│   ├── animation.js   … GSAP のアニメーション
│   └── form.js        … フォームの入力チェック・デモ送信
├── images/            … 画像（最初は仮画像のSVG）
├── docs/
│   └── SPEC.md        … この仕様書
└── README.md          … サイト概要、確認方法、画像差し替え手順、公開手順
```

### コーディングルール
- HTMLはセマンティックに書く（`header` / `nav` / `main` / `section` / `footer` など）
- 画像には必ず `alt` をつける。ファーストビュー以外は `loading="lazy"`
- CSSは色・余白・フォントをCSS変数で管理する
- パスはすべて相対パスにする（GitHub Pages のサブディレクトリでも動くように）
- 共通のヘッダー・フッターは各ページに記述してよい（ビルドなしのため）。内容は全ページで統一すること
- キーボード操作でもメニュー・フォームが使える。フォーカス時の枠線を消さない
- 各ページに固有の `<title>` と `meta description` を設定
- OGP（SNS共有時の表示）を設定
- 架空サイトのため、`<meta name="robots" content="noindex">` を全ページに入れる（実在の院と誤認され、検索結果に出るのを防ぐ）

## 10. 架空サイトの表記・文章ルール

### 架空サイトの表記（必須）
- 全ページのフッターに：「※このサイトはポートフォリオ用に制作した架空の整骨院サイトです。実在の店舗・人物・団体とは関係ありません。」
- ページ最上部に細い帯で：「このサイトはポートフォリオ用の架空サイトです」
- 電話・LINEボタンを押したときは、発信やリンク移動をせず「デモサイトのため、ご利用いただけません」と表示

### 文章の表現ルール（医療・健康系のため）
- 使わない表現：「必ず治る」「完治」「絶対」「即効」「地域No.1」「最高の技術」など、断定的・誇大な表現
- 言い換え例：「〜の改善をサポートします」「〜を目指します」「お一人おひとりに合わせて」
- 保険施術はケガが対象で、慢性的な肩こり・腰痛は対象外である旨を正しく書く
- お客様の声には「※架空のサンプルです」と明記する
- 文体は「です・ます」。やさしく、専門用語は使うなら短い説明を添える

## 13. Claude Code への実装手順の指示
1. フォルダ構成と共通部分（CSS変数、ヘッダー、フッター、架空サイト表記）を作る
2. `index.html` を完成させ、ユーザーに見た目を確認してもらう（**ここで一度止まって確認する**）
3. 残りの5ページを作る
4. `form.js` で予約フォームのデモを作る
5. `animation.js` で GSAP のアニメーションを入れる
6. 仮画像（SVG）・ロゴ・アイコン・ファビコンを作る
7. 375px / 768px / 1280px の3幅で表示を確認し、崩れを直す
8. 1章の完成条件をすべてチェックし、確認できなかった項目は「未確認」として報告する
9. `README.md`（概要、ローカルでの確認方法、画像差し替え手順、公開手順）を作る
